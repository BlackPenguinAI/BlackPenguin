## Architecture and scope
- `conversation_inspector.py` projects current scoped Hermes state, approved catalog names and prices, permanent preferences and temporary searches, CRM facts, visit drafts and native appointment records, material access and verified delivery evidence, run/tool observations and recent activity. It reads existing stores only; no writes, SDK inference, provider sends, database schema changes or secret/raw prompt/tool payload exposure. Tool observations remain ordered within their run time interval rather than assigning invented timestamps. Existing state fields and timestamps may be incomplete.
- Tenant access uses the existing project/role authorization plus exact company, project, lead and conversation checks, soft deletion checks, active opportunity and explicit attribution on reused threads. Direct conversation context and chat messages reuse these checks. Restricted meeting views cannot expose a complete conversation. Existing staff-only audited historical diagnostics remain separate.
- The operational-context endpoint adds `inspector_scope` and `hermes_inspector`; the previous LangGraph and shared CRM response remains intact. Unexpected optional projection failures expose a generic diagnostic error, not raw exception details. Authorization errors remain failures. The tenant Hermes endpoint preserves a small compatibility envelope; it is no longer used for a second polling request by Agent.
- `HermesInspectorComponent` is a standalone, read-only, four-section Angular component integrated in the shared `AgentContextComponent`. It reuses the existing 10-second refresh, clears stale results on selection or scope mismatch, and keeps existing operational context visible. Schedule continues to use meeting operational context. Chat timestamps include seconds in UTC; the inspector formats dates in the Project IANA timezone, or UTC if unavailable. No rendering of raw Hermes JSON. Message identity uses verified stored associations, not the globally selected engine; missing historical proof is explicitly unattributed. Links navigate to the existing chat messages; the activity window is bounded, so older sources may only be found in the full chat.
- The global activation gate and LangGraph configuration are unchanged. Hermes state from a prior engine/activation is never presented as a new actionable offer. The inspector shows recorded availability checks, not live slot guarantees. Provider acceptance is not device delivery. Catalog availability is not a share. A draft is not a confirmed visit. When no state exists, the panel says so and uses only available shared CRM/receipts. No fictional demonstration data is inserted.

Angular template compilation and execution of those cases could not be performed locally: Angular dependencies are absent and npm DNS failed. CI must validate them.
